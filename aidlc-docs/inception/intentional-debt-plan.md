# 意図的負債計画（Brownfield Before）

> 本作は仕様不明レガシーを **意図的に先置き**し、そこから Reverse Engineering → ドメイン抽出する。  
> 本番の事故再現が目的ではなく、**面談で「何が壊れていて、どこを境界に直したか」を説明できる粒度**にする。

## 置き場

| パス | 役割 |
|------|------|
| `legacy/` | Before（手続き型 PHP + mysqli 風） |
| After（未配置） | Step 1–3 承認後に Domain 境界で実装 |
| `aidlc-docs/inception/reverse-engineering/` | 仕様復元・アンチパターン一覧（Before 固定後に書く） |

## 埋め込むアンチパターン（計画）

| # | 負債 | レガシーでの現れ方 | After で示す解消 |
|---|------|-------------------|------------------|
| D1 | グローバル接続・SQL 連結 | `$conn` 共有、条件を文字列連結 | PDO／リポジトリ、プリペアド |
| D2 | 業務ルールの画面散在 | hold / confirm / release に同種 if が複製 | ドメイン不変条件＋ユースケース |
| D3 | 状態語のゆれ | `hold` / `OK` / `sold` / `free` が混在 | 明示的な状態遷移 |
| D4 | 期限チェックの抜け | 解放エンドポイントを叩くまで期限切れ席が塞がる／パスによって判定が違う | 「有効」の定義を Domain に集約 |
| D5 | 二重確保の穴 | 本確定済みだけ見て仮押さえ同士を許す、など意図的な抜け | 有効確保の一意（アプリ＋必要なら DB） |
| D6 | 照会と更新の混同 | 「空いてる？」が副作用を持つ／持たないが曖昧 | Query / Command 分離（Intent で確定） |

## 意図的に入れない負債

- 決済・会員・外部 API の巨大スパゲッティ（スコープ外を肥大化させない）
- 読めない難読化（復元不能はポートフォリオとして失敗）

## Before の受け入れライン（最小動作）

`make setup` 後、レガシー UI（または簡単な PHP 画面）から次が人手で辿れること。

1. 空席を仮押さえできる
2. 仮押さえを本確定できる
3. 期限切れ解放の入口がある（バッチ相当の URL／CLI）
4. 二重確保の失敗または抜けがデモできる（意図的穴 D5 を含む）

## 進め方との対応

1. 本計画を Intent と同時に残す ← **今ここ**
2. `legacy/` に最小実装を置く
3. Reverse Engineering で `spec-restored.md` / `anti-patterns.md` を書く
4. Step 2–3 承認後、After で D1–D6 を解消し受入 1:1 で証明する
